# DT—09

**Independent inquiry · Systems engineering**

I work across mathematics, computation, applied AI and systems engineering. I am interested in how ideas become models, how models become working systems, and how evidence tells us whether a result deserves trust.

The work moves between theory and implementation. An idea should survive contact with constraints. A system should make its behaviour inspectable. A claim should have somewhere solid to stand.

This profile is a record of projects, experiments and research directions at different stages of maturity. A repository listing is not a claim of production readiness.

## Questions I follow

- **Mathematics & computation** — Which abstractions, invariants and algorithms make difficult problems tractable?
- **AI & bounded agency** — What should intelligent systems be permitted to do, and how can that authority be evaluated?
- **Data & provenance** — Can a conclusion be traced through its source records and transformations?
- **Systems engineering** — How should software behave under failure, uncertainty and constrained resources?
- **Learning & scientific inquiry** — How does curiosity become a hypothesis, an experiment and a better model?
- **Design & interaction** — How can an interface expose complexity without concealing limitations?

The longer research agenda is in [RESEARCH.md](RESEARCH.md).

## How I work

**Question → Model → Build → Verify**

1. Define the problem, constraints and assumptions.
2. Choose an abstraction and make the mechanism explicit.
3. Implement the smallest system that tests the idea.
4. Test behaviour, expose limitations and revise.

## Engineering standard

A feature is not established because it appears in a roadmap, mock-up or marketing page. Project descriptions should distinguish implemented behaviour from planned work, and provide inspectable evidence for important claims.

See the [Portfolio Evidence Standard](PORTFOLIO_STANDARD.md) and [automated portfolio checks](.github/workflows/portfolio-checks.yml).
