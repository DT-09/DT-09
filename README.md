# DT—09

**Independent inquiry · Computational thinking · Systems engineering**

I work across mathematics, computation, applied AI, data systems and software engineering. My interest is the passage from an idea to a model, from a model to a working mechanism, and from a mechanism to evidence that can be examined.

I am drawn to problems with structure beneath the surface: algorithms, bounded agency, provenance, reproducibility, resilient execution and the design of tools that make complex work clearer.

This profile is a map of ongoing work and inquiry. Projects have different levels of maturity; each repository is the source of truth for its implementation, tests and limitations.

## 04 / The operating method

<div align="center">

**QUESTION** &nbsp; → &nbsp; **MODEL** &nbsp; → &nbsp; **BUILD** &nbsp; → &nbsp; **VERIFY**

</div>

1. **Question** — define the problem, constraints and assumptions.
2. **Model** — choose an abstraction and make the mechanism explicit.
3. **Build** — implement a reproducible system that tests the idea.
4. **Verify** — test behaviour, inspect evidence, expose limitations and revise.

A feature is not established because it appears in a roadmap, mock-up or marketing page. A claim should have somewhere solid to stand.

## 05 / Current principles

- **First principles over cargo cults.** Understand the mechanism before adopting the pattern.
- **Evidence over adjectives.** Prefer tests, traces and reproducible outputs to confident claims.
- **Boundaries over unchecked capability.** Define what a system can access and what it must refuse.
- **Clarity over ornamental complexity.** Every component should earn its place.
- **Curiosity with discipline.** Follow difficult questions; document what remains unknown.
